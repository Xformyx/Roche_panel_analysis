## 1. 개요

Roche Panel Analysis Web UI는 ctDNA 분석 파이프라인을 웹 브라우저에서 관리하는 인터페이스입니다.

주요 기능:
- 분석 오더 생성, 수정, 실행, 중지
- 실시간 분석 진행 모니터링 (로그 뷰어)
- 분석 결과 확인 (Variant, QC, Longitudinal)
- 시스템 리소스 모니터링
- 파이프라인 설정 관리

---

## 2. 접속

### URL

```
http://서버IP:포트번호
```

기본 포트는 `8080`이며, `.env` 파일의 `WEB_PORT` 값에 따라 다릅니다.

### 지원 브라우저

- Chrome (권장)
- Firefox
- Safari
- Edge

## 3. 대시보드

접속 시 가장 먼저 보이는 화면입니다.

### 3.1 오더 현황 카드

상단에 전체 오더 수, 실행 중, 실패, 완료 건수가 표시됩니다.
각 카드를 클릭하면 해당 상태의 오더 목록으로 이동합니다.

### 3.2 시스템 리소스

실시간으로 서버의 CPU, 메모리, 디스크, 파이프라인 슬롯 사용 현황을 보여줍니다.

| 항목 | 설명 |
|------|------|
| CPU | 서버 CPU 사용률 (%) |
| 메모리 | 사용 중 / 전체 메모리 (GB) |
| 디스크 | 사용 중 / 전체 디스크 (GB) |
| 파이프라인 슬롯 | 실행 중 / 최대 동시 실행 수 + 샘플당 할당 리소스 |

### 3.3 최근 활동

최근 업데이트된 오더 10건이 시간순으로 표시됩니다.

## 4. 오더 관리

좌측 사이드바에서 **오더 관리** 메뉴를 선택합니다.

### 4.1 오더 목록

모든 오더가 테이블 형태로 표시됩니다.

**필터링**: 상단의 상태 버튼(전체, 등록, 실행 중, 완료, 실패, 취소)으로 필터링합니다.

**검색**: 검색창에 입력하면 오더명, 환자이름, 샘플이름, 차트번호를 기준으로 검색됩니다.

**정렬**: 오더 생성일시, 결과 생성일시 컬럼 헤더를 클릭하면 오름차순/내림차순으로 정렬됩니다.

### 4.2 오더 생성

1. **새 오더** 버튼을 클릭합니다
2. FASTQ 파일을 선택합니다:
   - **찾기** 버튼으로 파일 탐색기에서 FASTQ 쌍(R1/R2)을 선택
   - 디렉토리를 탐색하며 원하는 샘플의 FASTQ 파일을 클릭
3. 오더 정보를 입력합니다:

| 필드 | 필수 | 설명 |
|------|------|------|
| 오더명 | O | 분석 오더의 이름 |
| 환자 이름 | - | 환자 성명 |
| 생년월일 | - | 환자 생년월일 |
| 차트번호 | - | 병원 차트번호 |
| 진료과 | - | 진료과 |
| 담당의 | - | 담당 의사 |
| 진단명 | - | 진단명 |
| 의사 코멘트 | - | 비고 |
| 레퍼런스 | O | hg38 또는 hg19 (기본: hg38) |
| AF Threshold | O | Allele Frequency 임계값 (기본: 0.005) |
| BED 파일 | - | 타겟 BED 파일 (미선택 시 기본 capture_targets 사용) |

4. **등록** 버튼을 클릭합니다

### 4.3 오더 수정

**등록**, **실패**, **취소** 상태의 오더만 수정할 수 있습니다.

1. 오더 목록에서 수정할 오더의 **편집**(연필 아이콘) 버튼 클릭
2. 정보 수정 후 **수정** 버튼 클릭

### 4.4 오더 상태

| 상태 | 설명 |
|------|------|
| 등록 | 오더가 생성되었으나 아직 실행하지 않음 |
| 실행 중 | Nextflow 파이프라인이 실행 중 |
| 완료 | 분석이 성공적으로 완료됨 |
| 실패 | 분석 중 오류 발생 |
| 취소 | 사용자가 분석을 중지함 |

## 5. 분석 실행 및 모니터링

### 5.1 분석 시작

오더 목록에서 **실행**(재생 아이콘) 버튼을 클릭합니다.

> 동시 실행 제한: 서버 리소스에 따라 최대 동시 실행 수가 제한됩니다.
> 제한을 초과하면 오류 메시지가 표시됩니다.

### 5.2 분석 모니터링

실행 중인 오더의 행을 클릭하면 하단에 **실시간 로그 패널**이 열립니다.

로그에서 확인할 수 있는 정보:
- Nextflow 프로세스 진행 상황
- 각 태스크(FastQC, BWA, VarDict 등)의 실행 상태
- 오류 메시지

로그는 5초마다 자동으로 갱신됩니다.

### 5.3 분석 중지

실행 중인 오더의 **중지**(사각형 아이콘) 버튼을 클릭합니다.
확인 다이얼로그에서 **확인**을 누르면 즉시 "취소 중..." 상태로 변경되며, Docker 컨테이너가 정지됩니다.

### 5.4 재실행

실패 또는 완료된 오더를 다시 실행할 수 있습니다:

| 버튼 | 설명 |
|------|------|
| **이어서 실행 (Resume)** | Nextflow 캐시를 활용하여 실패 지점부터 이어서 실행 |
| **처음부터 실행** | Work 디렉토리와 결과를 삭제하고 처음부터 재실행 |

## 6. 결과 확인

분석이 완료되면 다음 버튼이 활성화됩니다:

### 6.1 결과 Review (돋보기 아이콘)

VCF 파일의 변이 목록을 테이블로 확인합니다.

표시되는 정보:
- CHROM, POS, REF, ALT (변이 위치 및 서열)
- GENE, EFFECT (유전자 및 변이 효과 - SnpEff 주석)
- AF, DP, VD (Allele Frequency, Depth, Variant Depth)
- FILTER, TYPE, QUAL
- DBSNP_COMMON (dbSNP 등록 여부)

### 6.2 QC 결과 (파형 아이콘)

분석 품질 지표를 확인합니다:

| 카테고리 | 항목 |
|---------|------|
| Fastp | 트리밍 전/후 리드 수, Q20/Q30 비율, GC 비율 |
| 정렬 | 정렬률, 미스매치율, 키메라 비율, 어댑터 비율 |
| Insert Size | 중앙값/평균값/표준편차 |
| 중복 | 중복 비율, 추정 라이브러리 크기 |
| 커버리지 | 평균/중앙값 타겟 커버리지, 1x~1000x 비율 |
| Mismatch Rate | 미스매치율 |

### 6.3 파일 다운로드

| 아이콘 | 파일 |
|-------|------|
| VCF | 주석이 달린 VCF 파일 다운로드 |
| LOG | Nextflow 실행 로그 다운로드 |

## 7. Longitudinal 분석

> Longitudinal 분석은 배포 설정에서 활성화된 경우에만 사용 가능합니다.
> (`ENABLE_LONGITUDINAL=true`)

### 7.1 개념

Longitudinal 분석은 동일 환자의 시계열 ctDNA 샘플을 비교하여 VAF(Variant Allele Frequency) 변화를 추적합니다.

필요한 샘플:
- **Baseline**: 최초 조직 샘플 (기존 Baseline 분석 완료 필수)
- **Germline**: 생식세포 샘플 (정확한 변이 선별용, Baseline 분석 완료 필수)
- **Followup**: 추적 ctDNA 샘플 (현재 오더의 샘플)

### 7.2 Longitudinal 오더 생성

1. **새 오더** 클릭
2. 오더 유형에서 **Longitudinal** 선택
3. FASTQ 파일 선택 (Followup 샘플)
4. **Longitudinal Reference Selection** 섹션이 나타남:
   - **Baseline 오더**: 완료된 오더 중에서 Baseline 오더 선택
   - **Germline 오더**: 완료된 오더 중에서 Germline 오더 선택
   - **이전 Followup 오더** (선택사항): 기존 Followup 오더가 있으면 체크박스로 다중 선택
5. 나머지 정보 입력 후 **등록**

### 7.3 결과 확인

Longitudinal 분석이 완료되면 오더 목록에 **L** 배지가 표시되고,
**Longitudinal 결과**(파형 아이콘) 버튼이 활성화됩니다.

VAF 비교 테이블에서 확인할 수 있는 정보:
- 각 Followup 시점별 VAF 값
- 시간에 따른 VAF 변화 추이
- Baseline 대비 변이 상태

## 8. 파이프라인 설정

좌측 사이드바에서 **설정** 메뉴를 선택합니다.

### 8.1 리소스 설정

서버 리소스에 따라 분석 리소스를 조절합니다.

| 설정 | 기본값 | 설명 |
|------|--------|------|
| 최대 CPU 코어 | 0 (자동감지) | 파이프라인이 사용할 최대 CPU |
| 최대 메모리 (GB) | 0 (자동감지) | 파이프라인이 사용할 최대 메모리 |
| 최대 동시 실행 수 | 0 (자동계산) | 동시에 분석할 최대 샘플 수 |

> **자동감지**: 0으로 설정하면 서버의 전체 리소스를 감지하고,
> 샘플당 약 20 CPU / 30 GB 기준으로 동시 실행 수를 계산합니다.

**시스템 감지 결과** 패널에서 현재 적용된 값을 확인할 수 있습니다:
- 서버 CPU / 메모리
- 적용 CPU / 메모리
- 최대 동시 실행 수
- 샘플당 할당 리소스
- 현재 실행 중인 샘플 수

### 8.2 일반 설정

| 설정 | 기본값 | 설명 |
|------|--------|------|
| 기본 레퍼런스 | hg38 | 오더 생성 시 기본 레퍼런스 게놈 |
| 기본 Nextflow 프로파일 | Docker | Docker 또는 Offline |
| 기본 AF Threshold | 0.005 | 기본 Allele Frequency 임계값 |

### 8.3 Nextflow 설정

| 설정 | 기본값 | 설명 |
|------|--------|------|
| Resume 활성화 | ON | Nextflow 캐시 재사용 (`-resume`) |
| Work 디렉토리 자동 정리 | OFF | 완료 후 work 디렉토리 삭제 |

### 8.4 파일 관리

| 설정 | 기본값 | 설명 |
|------|--------|------|
| BAM 파일 삭제 | ON | 완료 후 BAM 파일 자동 삭제 |
| 중간 파일 삭제 | ON | 중간 파일 삭제로 디스크 절약 |
| FASTQ 소스 디렉토리 | `.env` 설정값 | FASTQ 파일 위치 (호스트 경로) |
| BED 파일 디렉토리 | `.env` 설정값 | BED 파일 위치 (호스트 경로) |

> 디렉토리 경로 변경은 `.env` 파일에도 저장되며 즉시 적용됩니다.
